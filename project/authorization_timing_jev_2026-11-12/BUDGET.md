# 拟定预算与停止条件

2026-11-12。本页是准备好的上限，**不是已执行用量或启动许可**。目前没有新模型调用、模拟器执行或集群作业。后续启动仍取决于用户取消“暂不启动”的指示；这不是新增收费或重新授权之前已完成的实验。

**v0.2 保持 v0.1 的全部资源上限。** 8 对改为 4 对基础、2 对隔着无关消息、2 对无关许可；另一位乘客的许可只是公开消息，没有第三次实际购买。额外文字在原上下文上限内预检，不增加调用、输出额度、smoke、重试或 GPU 分配。若无法满足原上限，停止并报告，不自动扩预算。预算对象的逐字值校验见[版本记录](DESIGN_REVISION.md)。

[TypeSafe 官方模型页](https://docs.typesafe.ai/models)在 2026-11-12 标示 Jev 为 **每百万输入 token $0.042**、输出免费，默认每 question 约 32k 上下文。本方案一请求一 question，不启用长上下文。按每次 32,768 输入 token 的保守容量计算：

`36 × 32,768 × 0.042 / 1,000,000 = $0.049545216`。

这是容量估计，不是实际账单；每次再向上预留 $0.002，使 36 次共预留 $0.072，低于 $0.10 客户端上限。实际计费 token、当前价格和账户余额在未来运行前重新确认。若价格或接口改变，重算预算，不无声扩充。GPU 只有配额预算，未取得价格就不合计成美元“总成本”。

实现时应使用可关闭自动重试的单次 HTTP 请求：每次先记账占用一次请求及预留费用，再发送；30 秒超时，串行调用，Jev 阶段最多 20 分钟。不因不确定是否收费而重发。API 返回异常、模型版本不符或 schema 失败时保存原始响应并停止。0.10 美元是待实现的客户端防线，不能写成账户供应商已经设置的消费限制。

Qwen 阶段同样先登记槽位，30 分钟 allocation 到时即止，缺失结果照原分母汇总。基础设施启动慢或 smoke 失败，不再申请第二个 allocation。未来适配器和预算控制尚待实现、离线验证；当前没有可误触发的提交脚本。

已有 27 份原始记录的真人复核另拟约 **2.5 人时**（两位同学各 45 分钟、共同讨论 30 分钟），不属于模型计算费。未来 8 对时序材料生成后，再预留一名同学约 20 分钟核对许可前后与程序标签；这些都是规划，未分配、未发生。
