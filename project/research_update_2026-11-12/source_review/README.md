# 来源复核：AI 已完成，真人复核仍待做

2026-11-12。复核者为 **Codex，处于已有作者上下文**。已看到程序参考标签、模型结果和上一轮审计，因此既不独立，也不盲审。不能写成“人工复核”“真人金标”或独立一致率。以下记录是研究准备材料，不是代写的课程最终报告。

## 实际做了什么

重新查看既定审计范围内的 **32 个 case（23 个预定、9 个探索性补充）** 的原始公开规则、用户许可、调用参数、成功回执及时间顺序。按完整 `record` 去重后为 **27 份不同记录**。逐案说明在 [AI_REVIEW_NOTES.json](AI_REVIEW_NOTES.json)，来源 ID、文件哈希和参考标签对照在 [AI_SOURCE_REVIEW.jsonl](AI_SOURCE_REVIEW.jsonl)。这是既有材料复核，没有抽取新样本、调用外部模型或运行模拟器。

对冻结规则的解释为 **9 条违规、23 条合规**，与已知程序标签全部一致，原标签未改。因为标签事先可见，不能把 32/32 写成独立验证准确率，也不能据此估计整个数据集的错误率。

本轮审的是原始动作的授权与执行事实。既有 C/F/T 回答和 Judge 错误解释的讨论仍引用[前一轮语义审计](../reports/semantic_audit.md)，不声称本轮又独立审完所有模型陈述。

## 真人复核包已经备好，但没有真人结果

- [HUMAN_SOURCE_PACKET.jsonl](HUMAN_SOURCE_PACKET.jsonl)：27 份去重的完整公开 record，保留原话、来源 ID、调用和回执；不附程序标签、模型分数或本次 AI 解释。
- [HUMAN_REVIEW_TEMPLATE.json](HUMAN_REVIEW_TEMPLATE.json)：所有判断、姓名和时间均留空，**完成数为 0**。
- [HUMAN_PACKET_KEY.json](HUMAN_PACKET_KEY.json)：单独的 case 映射。实际发给评审者时，只提供来源包、范围规则和空表，不提供映射或本页解释。

这只是**隐藏标签的材料包**。答案已在仓库中，是否可以称盲审取决于真实人员是否接触过标签和实际流程，不能靠匿名 ID 自动获得。建议两名未参与造标签的同学各独立看 27 份记录，分别填“严格规则结论”和“构造是否含糊”；预计各 45 分钟，再留 30 分钟共同处理分歧，合计约 **2.5 人时**，是规划额度，不是已完成工时。若只能一人复核，就如实写一人复核，不报告不存在的评审者一致性。

## 离线复现和边界

从仓库根目录运行 `python3 -B project/research_update_2026-11-12/source_review/build_packet.py`，只读取已发布压缩包和本轮手写 AI 注释，核验 5 个派生文件。`--write` 仅重建本目录的派生材料；不要覆盖同学已经填写的表，实际表应另存。

脚本核对原始归档字节哈希、选例范围、每个来源 ID 和去重结果，不调用模型、模拟器或集群。程序只能验证绑定和一致性，不能证明 AI 注释的语义判断正确。[机器摘要](AI_REVIEW_SUMMARY.json)保留这一限制。
