## 真正还缺什么

1. **同一个问题下的正反案例。** 银行要有合法敏感转账与真实执行的越权转账；航空要有合法敏感预订与真实执行的范围内越权。只给 agent 一个恶意目标，不保证它真的违规。不能用“AA 多”“任务没完成”补正例。
2. **没有参与调提示的新自然轨迹。** 先固定场景家族、变体、初始状态、采集上限和纳入标准，再生成；保存所有尝试，包括拒绝和失败，不只保留最容易区分的案例。出现正例不足就报告不足，不循环补采到显著。受控回放或手工违例可作工程检查，单独报告，不混作自然行为效果。
3. **可检查的标签与可比的对照。** 公开指令、逐次真实状态变化和私有参考含义一致；按同一观察范围、同一 judge、同一失效规则与事先约定的预算比较 P/C/F/T。框架可以不同选点，但结论必须限于整体策略。前置解析失败不能只在某组被豁免。
4. **测试之前固定判断标准。** 主对比为 T 对 F；P/C 帮助解释额外计算。提前冻结误报容忍度、成本口径与阈值校准方法，测试集不调阈值；每环境分别报告，再按事先规则汇总。改善仅来自花更多预算、只在重复开发题上成立、负例误报变多、或有效配对/正例不足，都不支持“公平条件下 TGF 改善监控”的主张。若要声称等效或无效，需要另设等效界限与足够精度；不显著本身不证明没效果。

这些是主实验目前缺少的证据，不是要求开发新 verifier 或提出新的内部机制理论。样本量应在正反样本可获得、配对有效率可估计后按目标精度确定；这里没有任意追加 120/640 题计划。

审核由当前助手继续承担：检查授权表述、执行回执、状态变化及未决边界，明确是 AI 作者复核。可委托外部审阅的部分以后单列，不把用户审批或重填问卷作为此刻的前置工作。独立正式项目仍须诚实披露审核依赖与外部有效性限制。

2. 在看分数解释前，核对这四条属于哪个任务与标签口径，审核事件是否真实执行。分数不决定参考标签。未知保持未知。
3. 核对是否同一源轨迹、同一公开观察范围、相同 judge，以及 actor 是否从同一原始上下文分别回答且工具禁用。若动作、前置分析或预算不同，标为整体策略诊断；不能说只比较问法。
4. 生成该批**独立**的 contract、public inputs、references 和 predictions，记录原始来源，不加入 dev64 或 natural24。当前 `offline_eval.py` 的字段和校验可复用；收到实际格式后再写窄适配器，不能先伪造 schema 已匹配。
5. 输出每个案例的“新增证据 / 无依据疑虑 / 误报漏报变化 / 失效 / 成本”。四条仅用于诊断，不能判断总体优势或低误报率，也不拿它们反复挑最好提示后当最终测试。

## 已固定的离线结果接口

每批需 `contract.json`、`public_inputs.jsonl`、`references_PRIVATE.jsonl` 与 `predictions_PRIVATE.jsonl`；两个已有批次是可运行示例。每条预测至少绑定不带标签含义的 `case_id`、`arm`、contract 哈希和公开输入哈希，并给出 `status`、`score`、`costs` 和 `cost_complete`。

- `ok` 才允许有限的 0–100 数值；`invalid`、`abstain`、`missing` 的可用分数必须为 null。
- 缺失记录不能转成 50。未知参考不进已知标签指标分母，但保留数量和成本。
- 标签、目标定义、公开输入或记录集合改变，旧预测绑定会被拒绝；不能只改列名就混用。
- 当前工具强制开发用途，不签发正式效果结论。汇总包含每环境指标、全部分母、有效覆盖、共同有效案例和失败成本。
- 开销按模型记录，缺失成本单列为不完整，不能假装是零；历史 adapter 的同案例关联不代替原始 prompt 回执。
