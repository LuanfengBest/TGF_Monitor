# 三组 SFT 恢复执行：数据与资源门槛

用户最新指令：“好的，那就按这个三组对照方案推进吧，先把数据和训练预检弄好，没问题就开始跑，需要我决策再停。”这授权恢复已有 base / ordinary SFT / evidence SFT 方案，通过门槛后直接训练和一次性评估；取代旧的 SFT 暂缓及 oracle-target 诊断待决定状态。oracle-target 不执行，也不是训练前置条件。旧冻结协议和结果不改写。

本轮仍为合成工具事件的小型组件试验，不证明 TGF 失败、微调必要、自然轨迹泛化或人类审核收益。旧四路结果仅支持提出证据关联/授权判断的训练假设。64 个训练目标、12 验证、24 final；底座修订、共同提示、量化、LoRA 配方、seed42、2 epochs、最后 epoch checkpoint 均沿用 tgf_sft_pilot_v1。普通组和证据组核心判断与 rationale 相同，仅三个辅助数组不同；实际监督 token/计算差异单报。

## 有限恢复预算

- 不生成新训练数据，不改 train/validation/final 家族。只修复已记录的 validation v011 故障注入：新版本覆写实际调用的 dict.pop，最多重新执行这一 case 的 1 个目标事件、3 次模拟工具 dispatch、30 秒本地 CPU。旧 v011 原始文件和标签完整保留；新验证集版本替换该 case，仍 12 个验证目标；最终 24 个原样锁定。先冻结代码/spec/source hash，再执行；这是预先已知的技术修复，不根据模型效果挑样。若发现其他标签/隔离问题，停止并记录，不扩大修复批次。
- 先只读检查集群队列、配额、旧运行时及残留权重。允许 1 个恢复 CPU 作业（32 GiB RAM、30 分钟、无 GPU），复用原官方固定修订，已验证完整文件用硬链接/只读复用，缺失文件串行流式下载并校验官方哈希，保留旧失败和 partial。总运行时与权重物理占用仍最多 90 GiB；不通过配额则不下载。无自动再次重试。
- GPU 仍沿用原未使用预算：预检 1×20 分钟、效果训练 2×45 分钟、三组固定评估 1×45 分钟；总最多 155 GPU 分钟。预检最多两次独立一步梯度测试、两次生成；评估 3×36=108 次生成。预检 adapter 不进入训练，两训练分别从同一底座初始化。资源不足不能静默换模型/配方。
- 本地代码/单元测试与只读远端检查不执行模型；每次集群提交先冻结来源和预算，保存唯一 reservation、job id、日志、成本，不重复提交历史作业。

## 门槛及决策出口

1. 重核 train 标签、证据指针和因果输入；两组输入/核心/rationale 逐例一致；prompt 和 padding 的 loss mask 正确；长度不截断；所有 split 家族与样本 hash 不重叠。新数据资格记录须引用旧审核、明确程序与非盲 AI 标签、非人工金标，人工抽检仍待完成。
2. 校验底座所有 22 个文件、固定依赖版本、空间配额；预检 finite loss/梯度、可训练参数、显存、padding mask、保存重载。门槛通过才标训练可用，不把下载成功当训练成功。
3. 训练前冻结代码/输入/顺序/评分口径；训练无需再询问。使用相同输入和输出 schema 固定评估，未见 final 不参与调整提示/超参/checkpoint；保留 unknown、失败和所有分母。
4. 报告三组核心判断、各域 TPR/FPR/G²（缺类则不算）、交付率、unknown、来源与语义支持。结构化数组的缺失和错误来源分开，不能仅以证据组更常输出数组宣称证据推理提高。核心判断和实质支持改善且误报/unknown 不恶化，才建议下一项接回 TGF 的有界研究；否则报告无增益/混合/不确定并收尾。不额外加 seed、重训、改 prompt 选优。
