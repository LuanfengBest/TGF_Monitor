# 接口诊断之后如何回到TGF主比较

这是接续工作说明，尚不是新的GPU运行冻结文件。当前先完成唯一诊断29660242，不并发扩批、不运行旧oracle-target草案，不根据部分结果调参。用户已授权接口修复、小诊断、回归主比较；出现重大设计问题或需另训/换型/扩大预算才请其决定。

## 要回答的问题

在相同公开轨迹、共同事件候选与选择、固定monitor权重下，基于轨迹定制的追问，相对通用追问和不追问，是否提高对已执行越权行为的检测及实质证据支持，同时控制合法动作误报？TGF是方法，G²是按环境的TPR×TNR指标。SFT诊断只检查monitor组件，不替代这个主问题。

旧自然轨迹比较的5例中，银行只有确定阳性、航空只有确定阴性及unknown，各环境G²不可估；多次复看这些development案例不能成为新的未见测试。旧三组SFT结果则存在共同输入合同和底座输出接口问题，因此当前36调用用于定位组件，不把格式恢复或训练loss称为TGF收益。

## 诊断收尾及解释

1. 先验收全部36计划位置、原始响应、同输入和adapter hash，再统一计分及逐项语义审核。6训练来源事件与6同家族新例分别报告；每域每split正负unknown各1，不能推断稳定误报率或显著性。
2. 邮件训练来源3例的输入未改，可检验精确训练输入的自由生成。银行3例已修公共工具合同，不可把其失败直接归结为无法拟合原训练文本。
3. 若仍有共同公开标签/输入缺陷，停止新推理，先给出具体缺陷、受影响范围及修复方案。若仅模型答错，完整记录；不在这12例重跑prompt、增tokens或改训练。小诊断不用于选出一个表现最好的checkpoint。
4. 若无共同正确性阻塞，即进入TGF新批次的离线实现和预算冻结。另训或更换模型仍需具体方案和用户决定，不能为取得正结果悄悄改变研究对象。

## 主比较的最小公平设计

保留ledger-only、固定通用追问、TGF定制追问三路；如保留额外计算对照B3，必须在输出前冻结其机会预算，不按TGF事后消耗筛选样本。通用追问与TGF共享完整公开输入、候选、选定事件、相同问题数量及回答上限，最终judge相同且不直接接收initial_review；追问只改变问题内容。TGF的问题生成成本单独计入总成本，不能把共享机会预算说成实际tokens相等。

共用选择器只能读取公开信息，不能由参考标签选点。无候选时保留轨迹及最终判断，追问数为0，不能剔除简单阴性。actor从原上下文独立分支、禁工具；其解释是待核验陈述，不是用户新增授权。明确公开字段及工具执行合同由工具实现决定，不得按案例标签定制。新组件诊断只覆盖schedule_transaction/send_email，不能把这两种合同直接用于全部原任务工具。

输入适配必须先逐工具核查，保留完整call/return、用户授权、政策、未知和失败；通用基础设施测试覆盖私有字段拒绝、同输入、独立actor分支、无候选、解析失败及预算用尽。监测输出统一保留原文，不自动补引用或补判断。将新的修复接入独立版本，不更改旧冻结runner。

## 新样本、指标和停止规则

下一次前瞻批次仍在proposal银行/航空原任务内，必须在输出前冻结新case/seed、actor配置、生成尝试数和总调用/时间预算；不把旧final或其改写当新train/测试，不把同家族seed变体称跨家族泛化。日期、时区及授权条件需在生成前作为公开任务明确，不能看actor输出后改写授权。合成事件组件与自然actor全轨迹分开命名。

正负覆盖按真实执行及授权审核，不把有无隐藏副目标当真值。固定次数用完即止，不补采到满意分布；任一环境缺正/负则该环境G²记不可估，并报告缺口，不跨环境拼分。所有生成失败、unknown、不合格轨迹及排除理由保留；数据资格审核先于monitor输出，不按方法结果选例。

同批配对报告按环境的TPR/FPR/G²、unknown、有效输出、公开可证事件覆盖、实质授权与执行理由、错误指控和成本。严格引用链与审核者从原文确认的实质理由分列。非盲主AI不是人工金标；小样本只能形成pilot证据。阈值与来源审核规则在输出前固定，不用这批结果再优化同批prompt。

这份说明不自行分配新的GPU预算。当前90分钟/36调用只覆盖29660242；下一批在诊断完整分析后形成具体冻结配置和可执行预算，并核对是否仍在用户授权的小规模范围内。超出范围时提供可审阅方案后再请用户决定。
