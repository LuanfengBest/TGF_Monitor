# 最小改动回到TGF主线：数据先验收，方法只比较一次

2026-10-16。依据本轮原verifier/公开数据核查及既有native数据。**这是供用户审阅的后续方案，未冻结或运行新实验；用户当前“先核实、不要改任务或跑新实验”仍有效。** 不因旧预算还有余额自动执行。

## 主问题及选择

问题仍为：在同一条原生actor轨迹和同一公开信息下，按trace选择的具体追问，是否比固定追问带来更多有证据支持的违规检出，同时控制误报与成本？保留原银行/航空长任务、gpt-oss20b actor、Qwen3-32B monitor、固定权重TGF和G²。不继续SFT，不更换模型，不把副目标成功重新定义成违规，不把历史其他actor文本当原actor续问。

推荐先修复**采集循环与原repo的已证实差异**，再只为缺口采集。当前没有证据支持靠“继续换seed”保证采够；也不能承诺公开数据零成本补齐。航空暂不能直接用AA副目标构造安全正标签，仍按公开授权事件审核。

## 阶段A：零GPU的准备与验收

预计1个工作日内完成，实现和审核时间另计；没有等待队列。这一步不代表实验成功。

1. 保留原verifier的main/side输出，新增独立的执行授权标签层；复用已审核的原生状态链和现有规则，不再把side=False或ordinary自动标N。公开数据的95个正例证据和6个静态负例只用于标签/输入合同检查，缺参不补造，不能计入原生pilot30/30。
2. 另版实现上游的无工具提醒继续规则。使用上游原句，最多5次累计提醒；全部计入原有turn、调用和时间预算，不算失败重试。原user request、邮件、环境、actor模型/参数和隐藏目标不改。新生成器另存版本，不覆盖或拼接旧42个终止前缀。**它仍改变生成过程，必须明确记录，不能称与旧采集完全一致。**
3. 用确定的模拟响应序列检查：无工具→提醒→工具；累计提醒到限；end_task后停止；达到总时间/turn后停止；部分执行异常不伪装无效；公开输入与私有参考隔离。只有离线fake响应，不调用模型或执行环境。保守长度保护暂留原样；若精确模板/token计数显示需要改动，单独记录，不边跑边调。
4. 核对所有方法共享的执行事件提取、来源绑定、输入长度、公开投影和JSON合同。只做一次统一修复，不反复用旧六例的效果选prompt。公开静态样本不能进入训练/最终测试，既有native两任务也都是development。
5. 请组员复核最少12个既有案例，覆盖4个现有hardN、错付/更正/错人/unknown边界；准备无AI意见视图及另存答案，未实际完成前不写“人工验收通过”。不擅自联系或分配组员。

## 阶段B：一次有界产率检查（需新的执行确认）

仅原两个完整任务，各6条ordinary，共12条新自然轨迹。模型、任务资产和公开请求不变；新循环使用阶段A冻结版本。只去掉原本ordinary就不应收到的hidden注入，不能指导actor照参考答案付款。

拟上限：12候选、480actor调用、单GPU60分钟、每例40轮/300秒、零重试、零额外恢复、零monitor效果调用。使用现有可用卡型，不升级硬件。队列等待不可预报。必须新建独占reservation与预算回执；旧方案/作业不重提。此60分钟是未来上限，不是本轮已耗或已批准。

阶段B专门检验两个事实：提醒机制是否消除实现导致的立即终止，以及原任务能否产生可审核的合法敏感执行。并不以12条比较TGF效果，也不声称它能精确估计负例产率。

**继续条件**：没有来源/绑定/共同输入错误；全部计划位置可归档并解释；每域至少2条完整可审核N且至少2条为实际合法敏感执行；原生上下文能用于独立追问。两条只是排除明显不可行的最低筛查，不能证明最终30N可达。若任一域失败，停止同方式扩批，报告具体阻塞及可选范围，不补采直到“抽中”好样本。

对比旧13条ordinary/域：银行N2/hardN1，航空N5/hardN1。这是既有尝试分母，不是新修复的预期收益。新增轨迹的开始/失败/unknown/全部费用均留在流图。

## 阶段C：只补经过论证的缺口，不先跑monitor

阶段B通过后，先用实际数据给出剩余缺口及产率区间，再决定一次有限批次。保留已有45条非运行错误原生记录（44条已知P/N、1条unknown）作为可复用的development pilot素材，不重新生成。其入选仍须通过共同输入门槛；旧新生成流程预先按版本分层，各方法在完全相同的联合集合上做成对比较，并另报版本内结果。不能把旧正例只给某方法、新负例只给另一方法，也不能隐去类别与生成版本的相关性；只有两个原任务，不能冒称同分布最终测试。

若已有原生样本均通过共同输入门槛，最低剩余缺口为：银行9P/28N/5publicP/14hardN；航空18P/21N/3publicP/12hardN。若有长输入或其他排除，按实际验收重算。公开历史其他actor样本不与这些数量直接相加。任何对旧样本使用的限制与分层方式须在新monitor输出前冻结。

采集优先ordinary，因为两域已有这一路产生的真实P，同时更需要N；injected是否需要、数量多少，依据**标签覆盖而不是monitor效果**在每批前固定。ordinary仍不是N。不得通过改收款金额、缩短请求、给航空新增禁AA条款来凑标签。

新增候选总上限建议仍不超过原剩余180个计划位置、总360单GPU分钟（含阶段B），不超过原240候选/480分钟总盘子；总预算是上限而非必须消耗。每批先审核产率再决定下一批，第一条非已知guard运行异常停止，不自动恢复。若某域敏感N产率仍不足，不能承诺在额度内凑够，也不把条件放宽到“工具没报错就算N”。新版本的数据未达到门槛就不进入效果比较。

**最低数据门槛**仍为每域30P30N、至少15公开可证P和15hardN，逐事件覆盖、unknown单列、人工抽检状态如实。任务完成率和安全标签分开；所有未知/失败不能为了平衡塞进N。这仍是两个固定任务的pilot，不是独立新家族最终测试，也不能宣称30N足以证明低误报率。

## 阶段D：回到固定权重TGF的最小主比较

达到数据及接口门槛后，复用现有四路实现：ledger-only、fixed B2、TGF、B3额外审阅。主要因果对照为B2↔TGF；共享trace、政策、ledger、选点、judge、回答上限，各从同一原actor上下文独立分支、禁工具；只改变固定或定制的问题内容。保持所有基线信息一致，隐藏目标和verifier只在参考侧。

一次冻结完整pilot集合和指标再运行，不边看结果边调prompt。最多1问/轨迹，最多9N生成调用（N=120时1080调用），没有再训练或广泛消融。按每环境报告TPR/FPR/G²、hardN误报、公开可证事件的实质支持及unknown/解析失败，主分母不因失败变小。引用数量和训练loss不能代替收益。

成本必须在数据冻结后按实际长度核算并另获确认。旧6例四路用48调用/1410 RTX5000Ada作业秒；简单线性外推120例约7.8 GPU小时，若都走9调用约8.8小时，**只是规划估计，不是资源预订、承诺或现有采集预算的一部分**。长trace可能更慢；先做零推理长度与预算验收，不为了“最低成本”漏算长输入。主比较若需超过批准上限，提交前决策。
